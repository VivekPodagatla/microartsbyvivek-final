# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

MicroArts by Vivek (microartsbyvivek.com): a storefront for handmade miniature art (artworks) and personalized pencil-carving gifts, plus a single-artist admin dashboard. Two independent npm projects plus a small shared folder, no root package.json:

- `backend/`: Express 5 + Mongoose (CommonJS), deployed on Render (`https://microarts-by-vivek-api.onrender.com`)
- `frontend/`: React 19 + Vite (ESM), deployed on Vercel
- `shared/`: dependency-free ESM modules used by both (designer rules and pricing), with the only unit tests (`cd shared && npm test`, Node's built-in test runner)

## Commands

```bash
# Backend (needs backend/.env: PORT, MONGODB_URI, JWT_SECRET, FRONTEND_URL, CLOUDINARY_URL;
# optional CALLMEBOT_PHONE + CALLMEBOT_APIKEY for WhatsApp alerts on new requests)
cd backend && npm run dev      # nodemon server.js (default port 5000)
cd backend && npm start

# One-off data migrations (connect via MONGODB_URI)
node backend/scripts/addArtworkSlugs.js
node backend/scripts/addProductSlugs.js

# Test data: creates one artist (test@example.com / test1234) if missing.
# Loads backend/.env itself and refuses to run unless the MONGODB_URI database is microarts_test.
node backend/scripts/seedTestArtist.js

# Frontend (needs VITE_API_URL in frontend/.env)
cd frontend && npm run dev     # Vite on :5173
cd frontend && npm run lint
cd frontend && npm run build   # vite build, then scripts/generate-seo.mjs
cd frontend && npx vite build  # bundle only: no API call, no SEO pages
```

`npm run build` calls the **live API** (`VITE_API_URL`, defaulting to the Render URL) to fetch artworks and personalized products. It fails if the API is unreachable, or if any item has a missing/invalid/duplicate slug. That default applies only to the SEO script. The app itself (`src/config.js`) has **no fallback** for `VITE_API_URL`, so it must be set in `frontend/.env` and in the Vercel project's environment variables, or every API call goes to `undefined/api/...`.

`npm run lint` also lints the untracked `src/App.backup.jsx`. To lint only live code, run `npx eslint src --ignore-pattern src/App.backup.jsx`. `App.jsx` has 11 known `react-hooks/*` errors (setState called directly in effects, and state setters used before their `useState` line). Don't fix them as a side effect: fixing them changes when the effects run.

## Architecture

### Backend
- `server.js` wires everything: it checks required env vars, sets CORS (comma-separated `FRONTEND_URL` allowlist; only GET/POST/PATCH/DELETE allowed), sets `trust proxy` for Render, applies rate limiters, mounts the routes under `/api/*` and adds a global error handler that maps CORS/multer/file-type errors to JSON responses. The app only listens after MongoDB connects.
- Routes: `/api/auth`, `/api/users`, `/api/artworks`, `/api/custom-requests`, `/api/personalized-products`, `/api/orders`, plus `/api/health`. Every response has the shape `{ success, message, ... }`.
- Auth: there is one artist/admin account. Public `/register` always returns 403. `/login` takes `{ identifier, password }` and returns a JWT. If the artist turned on authenticator-app 2FA (`User.twoFactorEnabled`, TOTP via `otplib`), `/login` instead returns `{ twoFactorRequired, challengeToken }` (a 5-minute JWT with `purpose: "2fa-login"`), and `/login/verify-2fa` exchanges it plus the 6-digit code for the real JWT. `authMiddleware` rejects any token that has a `purpose`. `/2fa/setup` → `/2fa/enable` turns it on from the dashboard's Account Security section; `/2fa/disable` needs password + code. TOTP secrets are `select: false`. Protected routes chain `authMiddleware` (Bearer JWT → `req.userId`) and then `artistMiddleware` (loads the user, requires `role === "artist"`, sets `req.user`). Public visitors never log in. They submit custom-art requests and gift orders (these POSTs are rate-limited by `publicSubmissionLimiter`).
- Media: artworks and gifts have a `media` list (`{ url, publicId, type: "image" | "video" }`, schema in `models/mediaItemSchema.js`). `image`/`imagePublicId` are kept as the **cover** (first image in `media`) because cards, the cart, orders and the SEO script read them; older items have only `image`, and `utils/mediaHelpers.js` `getMediaList` treats that as a one-image list. `uploadMiddleware` (`uploadMedia`) uses multer **memory storage**: up to 10 files in the `media` field (the legacy single `image` field is still accepted), JPG/PNG/WEBP ≤ 10 MB, MP4/WEBM/MOV ≤ 50 MB, at least one image required. Edits send `removeMedia` (URLs) and `coverMedia` (URL). Buffers go to Cloudinary through `utils/cloudinaryHelpers.js` with the right `resource_type`. Nothing is written to local disk.
- `utils/productSlug.js` `generateUniqueSlug` creates URL slugs for artworks and products. Slugs are required for the frontend's SEO pages.
- Models: `Artwork`, `PersonalizedProduct` (has stock/availability and `active`), `Order` (personalized gift requests), `CustomRequest`, `User`. Artworks and products have optional `seoTitle`/`seoDescription` and custom image alt text.

### Frontend
- **`src/App.jsx` (~2,000 lines) owns all state and behavior.** Every `useState` and `useEffect`, the `popstate` listener, the deep-link effects and every handler (`goHome`, `openArtwork`, `openArtistDashboard`, `handleSubmitOrder`, the dashboard CRUD handlers, ...) live there. Its JSX picks the view through one ternary chain, in this order: order success → checkout → login → cart → artist dashboard → artwork detail → gift detail → personalized list → home. Each branch renders one component, except the dashboard branch: it is still an inline `<section>` with the tab bar and the section components. The custom-request modal, toast and confirm dialog render beside that chain. Search App.jsx by section comment banners (`// ===== ... =====`) rather than reading it top to bottom.
- There is no router library. Views switch through `useState` flags (`selectedArtwork`, `showPersonalized`, `showProduct`, ...), and URLs sync manually with `window.history.pushState`/`replaceState` and the `popstate` listener. Deep links `/artworks/:slug` and `/gifts/:slug` are resolved in `useEffect`s once the data has loaded.
- **Layout of the other files:**
  - `src/config.js`: `API_URL` (from `VITE_API_URL`, no fallback).
  - `src/api/`: one file per resource (`artworks`, `personalizedProducts`, `orders`, `customRequests`, `auth`, `users`). Each wrapper returns the **raw `fetch` promise**. Callers do their own `response.ok` / `response.json()` checks, messages and state updates. Artist wrappers take the token as their first argument. FormData uploads (artwork/product add/edit and the stock/active/featured toggles) send only the Bearer header and must **not** set `Content-Type`, so the browser can add the multipart boundary.
  - `src/utils/`: pure helpers. `images.js` (`getImageUrl`, `getArtworkImageUrl`), `pricing.js` (`calculatePersonalizedPrice`, which mirrors the backend's order pricing) and `notifications.js` (`classifyNotification`, `titleByType`).
  - `src/components/`: shared chrome. `Navbar`, `Footer`, `Toast`, `ConfirmDialog` and `PopupStyles` (the inline `<style>` for the toast/confirm popups).
  - `src/views/`: the public pages, one per ternary branch (`Home`, `ArtworkDetail`, `GiftDetail`, `PersonalizedGallery`, `Cart`, `Checkout`, `Login`, `OrderSuccess`), plus `CustomRequestModal`.
  - `src/dashboard/`: the artist dashboard sections (`DashboardHome`, `CustomRequestsSection`, `OrdersSection`, `ProductsSection`, `FeaturedArtsSection`). The dashboard's tab bar and its `artistDashboardSection === "..."` switch are still inline in App.jsx.
- **Component rules:**
  - Every component is defined at **module level**, one per file, with a single default export (the `react-refresh` lint rule requires this). Never define one inside `App`. A new identity on each render would remount it and wipe the uncontrolled inputs: the `FormData` request form and the dashboard edit forms with `defaultValue`.
  - Components receive state, setters and handlers as **flat props under the same names as in App** (`setShowCart={setShowCart}`).
  - Components are pure markup: no hooks, state or effects of their own. They import the `utils/` helpers they need. The exceptions are a few inline handlers moved over unchanged from App.jsx. The gift card `onClick` in `PersonalizedGallery` and the back button in `GiftDetail` call `replaceState`/`pushState`, and the `CustomRequestModal` form's `onSubmit` reads `FormData` and posts via `createCustomRequest`. Keep those calls exactly as written.
  - Don't add wrapper elements. Multi-root views return the existing `<>…</>` fragment, and `id="gallery"` (the `scrollIntoView` target) lives in `Home`.
- The JWT is stored in `localStorage` as `authToken`.
- `html` has `scroll-behavior: smooth`, and on phones a smooth scroll is cut short when the page underneath changes. Handlers that switch to a new page should call `jumpToTop()` (App.jsx: instant scroll now and after the next paint) rather than a smooth `window.scrollTo`; `openPersonalized` and `openDesigner` do.
- The artist login is **not linked anywhere**. It opens only at `/studio` (`showLogin`'s initial state checks the path; `vercel.json` rewrites `/studio` to `/index` with a `noindex` header; with `cleanUrls` on, a rewrite to `/index.html` 404s). The dashboard keeps the URL at `/studio`. `openArtistDashboard` is a hoisted `function` declaration so the profile-loading effect can call it when `/studio` loads while already signed in.
- Gift category filter: `giftCategories` / `filteredPersonalizedProducts` are derived in App from each product's `category`; the chips render only when at least one gift has a category. The search bar (`giftSearch`) narrows that list further: every typed word must appear in the gift's title, category or description.
- `components/MediaGallery` (detail pages) and `dashboard/MediaFields` (add/edit forms) are the shared media UI. `MediaGallery` uses CSS scroll-snap; its thumbnail `onClick` scrolls the track through the DOM, so it stays hook-free.
- **Designer ("Design Your Gift Idea", `/design`):** a customer tool to design pencil arts and frame them. It lives in `src/designer/` and is lazy-loaded from App (`showDesigner`, `openDesigner`), which only opens and closes it. It is the **one exception to the hook-free component rule**: its state lives in `designerStore.js` (a plain object `S` plus actions, read through `useSyncExternalStore`), ported from Vivek's prototype. `refresh()` renders with `flushSync`, then measures the board DOM for `keepIn` (nothing leaves the frame) and `separate` (pencil arts never overlap), so store actions must run from event handlers, not during render. `pencilArt.js` (pencil SVG, canvas lead mask, distance transform) and `photoShapes.js` are ported **unchanged** from the prototype; their output was verified byte-identical, so treat their constants as tuned values. Pencil fonts are self-hosted (`@fontsource/*`, plus `designer/fonts/MagnoliaScript.otf`, free for commercial use per Vivek); the 28 quote fonts load from Google Fonts only on that page. Prices come from `shared/designPricing.js`; the backend must recompute them, never trust the browser's total. Entry buttons ("Design Your Gift Idea") are on Home, Personalized Gifts, every artwork page, every gift page (`GiftDetail`, hidden when out of stock) and the custom-request form. Gift and artwork pages call `openDesigner({ type: "gift" | "artwork", slug })`, which opens `/design?gift=<slug>` or `/design?artwork=<slug>`; App keeps `designerSource` (read from the URL, also on refresh and Back/Forward) and passes the matching `designerGift` / `designerArtwork`, shown in `SourceBanner`. Only the design is charged (frame, printing, pencil arts); the gift is a reference the request is sent with ("Designing for"), and its own price is **not** added. The design total is the customer's final price. An artwork is likewise only a reference ("Inspired by"). Gifts bought without designing keep their normal per-letter pricing. Other buttons call `openDesigner` with a click event, which means "no source". `openDesigner` pushes the history entry with `fromSite: true`; the designer's back button (`leaveDesigner`) then does `history.back()` to the page it came from, and on a shared link (no `fromSite`) goes to the gift or artwork in the URL, or home. Desktop (≥ 900px) uses two columns (sticky preview left, tools right); `boardScale()` in the store mirrors the column widths in `designer.css`. Spec: Vivek's designer CLAUDE.md (phases 1-3). All three phases are built; Phase 4 (templates, wall preview, undo, payments) is for later.
- **Dashboard → Design Requests (Phase 3):** `src/designer/admin/` (lazy-loaded from App's dashboard section `"designs"`; own state, like the designer). The list filters by status; the detail view shows the overall design (redrawn with `renderDesign` from the uploaded photos, zoomable), carving details per pencil (text, font, pencil, ends, each symbol and colour), frame specs, price, customer with WhatsApp (`wa.me`) or Call link, photo downloads (Cloudinary `fl_attachment`) with placed-DPI warnings below 150, status, private notes and delete. **Print file** (`printFile.js`): `renderDesign` at 300 DPI with no frame and no pencils, original photos, clear glass → transparent; PNG gets a `pHYs` chunk, PDF (jsPDF, loaded on demand) has a page of exactly the art size. Name `<ref>-<customer>-<size>-print.png/.pdf`. Fonts for the designer and this view load through `designerFonts.js`.
- **WhatsApp alerts:** `backend/utils/notifyArtist.js` messages Vivek through CallMeBot after every customer submission is saved: design requests (`notifyNewDesignRequest`), custom art and contact requests (`notifyNewCustomRequest`) and personalized gift requests (`notifyNewOrder`). Not awaited; failures only logged.
- **Phone fields on every customer form:** the custom request / contact modal and the gift checkout use `components/PhoneFields` (country-code dropdown from `shared/contactRules.js`, number, "This number is on WhatsApp") and `components/ConsentCheckbox`, like the designer's send step. They send `countryCode`, `phone` (without the code), `hasWhatsapp` and `consent`; the routes check them with the shared `validatePhone` and store `phone` as the full number (`"+91 98765 43210"`, so older dashboard code keeps working) plus `countryCode`, `hasWhatsapp`, `consent`. A body without `countryCode` (a page loaded before this change) still gets the old single-string check. The dashboard shows the number with `components/PhoneWithWhatsapp` (WhatsApp chat link, or "no WhatsApp"). Needs `CALLMEBOT_PHONE` and `CALLMEBOT_APIKEY` in `backend/.env` and on Render; without them it does nothing. The link in the message uses the first non-localhost `FRONTEND_URL` (falling back to microartsbyvivek.com) + `/studio`. CallMeBot drops "$", so the total is written as "Total: 33 USD".
- **Design requests (Phase 2):** step 3 "Send" (`SendStep.jsx`, `sendDesign.js`) checks the design and contact with `shared/designValidation.js`, wakes the Render server (polls `/api/health` for up to 2 minutes), renders a preview PNG with `renderDesign.js`, then POSTs multipart to `/api/design-requests` (design JSON, contact, `photoIds`, optional `giftSlug`/`artworkSlug`, original `photos`, `preview`). The draft (design + contact) autosaves to localStorage (`microarts-design-draft`); original photos live in IndexedDB (`photoStore.js`) and the board copies are rebuilt on reload; both are cleared only after the server confirms. Limits: 8 photos, 10 MB each (`MAX_PHOTOS` in shared rules, `MAX_DESIGN_PHOTOS` in `uploadMiddleware`). `renderDesign(design, { ppi, includeFrame, includePencils, includeBackground, clearAs, photoSource })` is the one renderer for preview, dashboard and print; it paints pencil SVG itself (no `<img>`), so fonts and lead fill always appear.
- Backend `routes/designRequestRoutes.js` + `models/DesignRequest.js`: public POST (rate-limited, validated, price recomputed with the gift loaded from the DB, files to Cloudinary `microarts/design-requests/<id>/`, cleaned up on failure); artist-only GET list (`?status=`, without the design), GET one, PATCH status/notes (status history kept), DELETE (also deletes the Cloudinary files). The backend loads `shared/` through `utils/sharedDesign.js` (dynamic `import()`); `server.js` loads it before connecting, so a deploy that can't see `shared/` fails at startup.
- SEO pipeline: after `vite build`, `scripts/generate-seo.mjs` writes a pre-rendered `dist/{artworks,gifts}/<slug>/index.html` for each item (title, meta/OG/Twitter tags, canonical, JSON-LD `VisualArtwork`/`Product`, with no Offer on purpose) and regenerates `dist/sitemap.xml`. Only gifts with `active: true` are included. `vercel.json` rewrites `/artworks/:slug` and `/gifts/:slug` to those files.

## Conventions
- Backend code uses a very vertical style: one argument or value per line, with `// ===== SECTION =====` banner comments. Match it when editing.
- `*.backup` / `App.backup.jsx` files are untracked manual backups. Don't edit them, and don't treat them as live code.
